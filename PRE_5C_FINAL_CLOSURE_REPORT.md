### Defects found by this run and fixed (with regression tests)
1. **Session revocation did not work (auth defect).** A session cookie copied before logout kept working until JWT expiry, and the same for password change/reset (`deleteAllUserSessions`), because only the JWT signature was verified and the `sessions` row was never consulted. Fix: `requireAuth()` now also requires a live, unexpired `sessions` row for the `(sessionId, userId)` pair (`src/lib/middleware/require-auth.ts`, `auth/repository.ts#findActiveSession`, `auth/service.ts#isSessionActive`); `resend-verification` moved from `getCurrentSession()` to `requireAuth()`. Cost: one primary-key lookup per authenticated request. The HTTP suite now asserts the copied token is refused by `/auth/me` and `resend-verification`, and that a token whose sessions were deleted is refused. The remaining `getCurrentSession()` callers (marketing CTAs, `logout`) are documented in `docs/ARCHITECTURE.md`. *Note: the first HTTP run before the fix failed this check (200); an intermediate rerun hit a stale server process still holding the old route code — the final 94/94 is from a fresh server started after the final build, with the server's response message confirming the new code.*
2. **Wrong status for a foreign `businessId` on AI execute:** the orchestrator wrapped the access check's `ApiException` as `UNKNOWN_PROVIDER_ERROR` (502 "AI generation failed"). Still fail-closed, but misleading. Now surfaced as the original `NOT_FOUND` (404)/`FORBIDDEN`; unknown non-API errors are still masked.

New unit tests: `require-auth.test.ts` (5, mutation-checked: disabling the check fails 4), `session-active.test.ts` (3), `orchestrator-authorization-errors.test.ts` (3). These use doubles and are separate from the real-service suite.
